# Bingr voor LG webOS TV: werkafspraken

- Deze repo is de LG-tv-app van Bingr: een web-app voor webOS (HTML5, `appinfo.json`, `.ipk`). De app zelf is de Samsung TV-app uit LRvdLinden/bingr-android (map `tizen/`): die code komt bij het bouwen uit die openbare repo op de vaste commit in `upstream.properties` (`tools/build_app.py`, anoniem, geen token). Hier staat alleen wat webOS-specifiek is: `platform/webos-logic.js` (pure logica), `platform/webos.js` (apparaat, Luna-systeeminfo, Magic Remote, speler met mpegts.js-terugval, afsluiten), `platform/webos.css`, `platform/patches.json` (kleine tekstvervangingen in de gedeelde code), `appinfo.json`, `assets/` en de packaging. Functies van de app zelf (schermen, speler, account, sync, support) horen in bingr-android/tizen, niet hier.
- Gedeelde code bijwerken: `UPSTREAM_COMMIT` in `upstream.properties` op de nieuwe commit van bingr-android (volledige SHA), `python3 tools/build_app.py`, tests draaien. Stopt de build op een patch ("x keer gevonden, verwacht 1"), dan is de gedeelde code veranderd: pas `platform/patches.json` aan. Niets in bingr-android wijzigen zonder overleg (daar werken anderen tegelijk).
- Openbare repo: geen geheimen, persoonsgegevens of logs met servergegevens in bestanden, commits of workflow-logs. Secrets alleen als GitHub-secrets (zie README.md). De publieke Supabase-URL en de publishable key (in de gedeelde code) mogen erin.
- Versie en build staan in `version.properties` (`BINGR_VERSION`, `BINGR_BUILD`); daarna `python3 tools/set_version.py` (zet ze in `appinfo.json` als `1.0.<build>`, bijv. `1.0.147`, en in `package.json`/`package-lock.json`; de workflow controleert dat met `--check`). De app-id blijft altijd `nl.lrvdlinden.bingr` (zelfde als Apple en Android); een andere id installeert als nieuwe app.
- Buildnummers zijn één doorlopende reeks met de andere apps: een nieuwe build krijgt het volgende vrije nummer (hoogste build in `docs/changelog.json` van LRvdLinden/iptv-ios-appletv + 1). Alleen verhogen als de LG-app echt verandert (platformlaag, packaging of een nieuwe `UPSTREAM_COMMIT`); wat niet verandert, krijgt geen nieuwe build.
- Bij elke build:
  - Een item in `docs/changelog.json` van iptv-ios-appletv met platform **`webos`** (alleen de punten die echt voor de LG-app gelden; "Alle apps" omvat vanaf build 147 ook `webos`).
  - Daar `python3 tools/make_changelog.py --webos ../bingr-webos` draaien en `CHANGELOG.md` hier committen **vóór** (of samen met) het ophogen van de build: de workflow haalt de release-notities voor het beheer uit de sectie `Build <n>`.
  - Daarna de stappen van iptv-ios-appletv (o.a. `tools/sync_website.py`), zodat de build op bingr.online/changelog staat.
- Buildpakketten (de `.ipk`) **nooit** op GitHub: niet in een repo, niet als release, niet als (onversleuteld) artefact. De workflow *Build* levert ze alleen versleuteld aan bij de **privé** repo LRvdLinden/bingr-inbox (`tools/seal_build.sh` uit bingr-beheer, anoniem gekloond; platform `webos`; secret `BINGR_INBOX_TOKEN` met alleen Contents: write op bingr-inbox, nooit in een URL). De workflow *Builds* van bingr-beheer zet ze in de afgesloten map `builds/` op de server; downloaden alleen via het beheer (tab Downloads, kortgeldige link). Ontbreekt `BINGR_INBOX_TOKEN` (of kent `seal_build.sh` `webos` nog niet), dan niets aanleveren (::notice::, wel groen). Nooit een schrijftoken op bingr-beheer in deze repo.
- GitHub Actions vast op een commit-SHA (tag als commentaar). Versies van de webOS CLI (`@webos-tools/cli`), mpegts.js, terser en acorn liggen vast in `package.json` en `package-lock.json`; Playwright in de workflow op een vaste versie.
- Tests: `node test/platform_test.js` (unittests van de platformlogica), de logica-tests van de gedeelde code (`.upstream/tizen/test/*_test.js`), de compatibiliteitscontrole (`check_compat.js`) en `python3 test/smoke.py` (headless Chromium met de neppe backend van de Tizen-tests en een LG-stub). Nieuwe platformlogica krijgt een unittest; nieuw gedrag op de tv een controle in de rooktest.
- Na elke push: `gh run list -R LRvdLinden/bingr-webOS` (workflow *Build* geslaagd), en binnen 15 minuten *Builds* in bingr-beheer (annotatie "webos build <n> op de server gezet"). De logboeken staan op de branch `ci-logs` (`latest.txt`, `build.log`, `unit.log`, `shared.log`, `package.log`, `smoke.log`, schermafbeeldingen `webos-*.png`). `gh workflow run` werkt hier niet; starten via `gh api repos/LRvdLinden/bingr-webOS/actions/workflows/build.yml/dispatches -f ref=main`.
- Commitberichten in het Nederlands.
